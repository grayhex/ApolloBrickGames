# Сверка аркад с оригинальными ROM

18 октября 2026. Продолжение [первого ревью](rom-review.md). Эталон — исполнение оригинального машинного кода в [BrickEmuPy](https://github.com/azya52/BrickEmuPy/tree/376cca92c6d000ffd6046e5491f2a1c3d1a5eab0), ревизия `376cca92c6d000ffd6046e5491f2a1c3d1a5eab0`. Mario не меняется. Параметры одной прошивки не объявляются общими для всех устройств.

## Как воспроизвести

```sh
git clone https://github.com/azya52/BrickEmuPy /tmp/BrickEmuPy
git -C /tmp/BrickEmuPy checkout 376cca92c6d000ffd6046e5491f2a1c3d1a5eab0
python scripts/research/brickemu_arcade.py \
  --upstream /tmp/BrickEmuPy --output /tmp/rom-arcade.json
diff tests/fixtures/brickemu/rom-arcade.json /tmp/rom-arcade.json
```

Нужен Python standard library; PyQt, звуковое устройство и реальное ожидание каждого игрового шага не нужны. Стенд проверяет чистоту checkout и считает **циклы CPU**, используя штатные CPU, Interconnect, DirectInput и звуковой декодер upstream. Время определяется частотой конфигурации устройства, а не скоростью Python. Это частоты эмулятора, не измерение физических RC-генераторов.

Режимы `--section catalog|snake|dice|audio|frog|beetle` позволяют повторить отдельный опыт; `inventory` отдельно сохраняет запуск каждого устройства. Fixture содержит хеши ROM/SVG, вход, циклы и исходные клетки/результаты; ROM и код эмулятора в приложение не включены. Карты `device-lcd.json`, `b0202-lcd.json`, `e23-lcd.json` получены из оригинальных SVG. Совпадение всех 200 адресов E88 и E-23 проверено; E33 использует другую карту.

В обычных тестах сеть не нужна. `rom-arcade.test.ts`, `rom-frog.test.ts`, `rom-beetle.test.ts` сравнивают поведение нашего движка с этими независимыми наблюдениями, включая 1296 бросков и длительные интервалы. Проверки сцен и таблиц не заменяют прохождение всех режимов ROM.

### Исправленная идентификация

E-23 №93 / E88 №5 в первом ревью ошибочно названы мячом с ракеткой. Это змейка: стартовый горизонтальный хвост из трёх клеток находится снизу, пища мигает, поворот переносит голову, обратное направление разворачивает всё тело. Поэтому прежнее предположение о новом Arkanoid по этим ROM снято. Существующие Arkanoid/Pong не меняются на основании этой ошибки.

## Snake: E88 №5 / E-23 №93

- Начало: голова `(5,0)`, хвост `(3,0)`, координата y отсчитывается снизу. До этого наша змейка начинала в середине.
- ROTATE означает **вверх**, а не ускорение. Новое направление сразу делает шаг. Удержание ROTATE не даёт turbo.
- Противоположное направление меняет местами голову и хвост, разворачивая путь целиком; дополнительного шага в этот момент нет. У изогнутого тела направление определяется бывшим хвостом. Остаток таймера сохраняется.
- Убраны придуманные внутренние стены основного варианта. Отдельная «Рамка» остаётся реконструкцией по вики.
- Плод даёт +10. Существовавшие 13 плодов до перехода и бонус +100 **пока остаются адаптацией**, не доказанным полным циклом ROM. Четыре жизни согласуются с последовательностью индикатора E88.

Десять медиан обычного шага в E88 при 1 МГц: **332,358 / 299,334 / 266,316 / 233,764 / 200,738 / 168,178 / 135,156 / 102,128 / 70,056 / 37,038 мс**. E-23 независимо даёт близкие значения. Измеряется серия шагов, без интервала появления еды: перерисовка еды может задержать следующий шаг. Движок переносит дробный остаток между кадрами 60 Гц, не округляет каждый период независимо.

### Звук

Штатным `HT4BITsound` декодированы SROM-каналы E88 **0 / 5 / 11 / 12 / 13 / 14**: движение, еда, столкновение, выигрыш, конец, старт. В `e88Effects.ts` сохранены частоты и длительности, а не сэмплы/ROM-байты. Новая команда прерывает предыдущую, как единственный канал оригинала; приоритет мелодии больше не заглушает игровой сигнал. Пауза/выключение отключают генераторы.

Пищалка синтезируется квадратной волной с короткой огибающей и детерминированной шумовой модуляцией. Это воспроизведение команд декодера, не точная аналоговая модель динамика или шума микросхемы. Сигналы непроверенных игр не объявляются оригинальными.

## Dice: Apollo B0202 E02

По решению владельца прежнее угадывание суммы трёх костей заменено **четырьмя костями со ставкой и банком**. Перенесён один раунд E02 «банк против игрока». E01 (серия раундов) и E03 (сравнение двух банков) не выдаются за реализованные варианты.

Подпрограмма `$189B`, bank 1 (физически `$289B`) выполнена для **всех 6⁴ = 1296 комбинаций**. В тесте явно задаются только четыре нулевых значения граней `$96..$99`, счётчик команд и банк; код ROM не меняется. `0` — переброс, `255` — четыре одинаковых; обычное внутреннее значение увеличивается на 2 для отображаемых граней.

- Есть одна пара — сравнивается сумма остальных костей; две пары — сумма старшей пары. Без пары и при тройке нужен переброс. Четыре одинаковых — особый исход.
- Стандартный банк 1000. RIGHT оплачивает единицы ставки по 10, предел 100; банк уменьшается сразу.
- START/P перед броском меняет больше/меньше, ROTATE запускает бросок, DOWN останавливает. LEFT показывает бросок банкира. Отдельная кнопка паузы сайта действительно останавливает игру.
- Сначала банкир, затем игрок. Четыре одинаковых у банкира забирают ставку. Обычная победа возвращает ставку ×2, четыре одинаковых у игрока — ×4. Ничья сохраняет оплаченную ставку на повтор; второй раз она не списывается.
- После банкротства публичный результат — **наибольший банк именно этой партии**, по согласованию с владельцем. Во время игры табло показывает текущий банк. Исторический hiScore не подставляется вместо результата.

ГСЧ, смена картинок броска и удержание результата одну секунду — адаптации. Звук Dice пока общий синтезированный, не измеренный набор B0202 E02.

## Frog: Apollo B0202 A01

Основной вариант заменяет донорскую дорогу из восьми полос с переходами по два ряда. Варианты 02–16 сохраняют прежние правила донора; номера не сдвигаются.

- Старт `(5,0)`, переход по одной строке; с 17 на 19. За переход **speedDigit+1**, без заполнения десяти домов и бонуса за них. На 1000 очков SPEED повышается, на 100 — нет; максимум сохраняется. Границы проверены отдельными постановками счёта 99/999/990.
- Полосатые островки на y=5 и 11: `##..##..##`. Изначально трафика нет.
- Таблица расписания bank 1 `$1227` (физически `$2227`), длины групп `$11F7` / `$21F7`. Три группы по пять рядов с разными направлениями. Последовательность **A,B,C,A,B,A**: шестая запись возвращает смещение и повторяет A, а не C. Это проверено шестью последовательными кадрами ROM.
- Период группы `(20−2×speedDigit) × 25 × 2048 / 690000` с; отдельная начальная задержка `5 × 25` тиков ROM. Лягушка переносится движущимся рядом; попадание в занятую клетку/за край отнимает жизнь.
- Мигающий успешный переход измерен в 1935,820 мс; затем возврат к старту.

Равенство генератора случайных групп, полный набор поздних таймерных опасностей и сцены смерти не установлены. Сохранены четыре жизни и адаптированная секундная пауза смерти; счётчик попыток ROM требует отдельной проверки total/spares. Поэтому это профиль подтверждённых геометрии/движения/очков, а не полная побитовая копия A01.

## «Пчёлки»: Apollo B0202 D01 Beetle

По подтверждению владельца Beetle становится **основным вариантом 01**. Остальные семь вариантов с фигурой/ответным огнём, переворотом и двумя стволами сохранены.

Выполнены подпрограммы движения `$1DD5`, пушки `$1DB9`, выстрела `$1EBF` и замены/счёта `$1F25`. Начало: четыре одноклеточных жука `(0,16),(2,16),(4,16),(6,16)`, пушка в `(4,0)`. Жуки делают диагональный шаг на одну клетку, переходят через боковой край. Промахнувшийся мимо пушки жук возвращается на y=16; контакт с пушкой на нижней границе отнимает жизнь.

Одно нажатие — один луч до первого жука, без автоогня при удержании. Прямой выстрел не разрушает верхний резерв. За жука **+1**, вместо него расходуется крайняя правая клетка нижнего из непустых рядов резерва (y=17…19). После расходования резерва меняется рисунок, без нашего старого бонуса +100. Маски резерва считаны из ROM `$2197`, период шага — таблица `$0C38`, как у B0202. Каждые 1000 очков скорость растёт до предела, после цикла рисунков переходит по кругу.

В hit-пробах явно построены один жук и клетки LCD; оригинальная процедура стрельбы выполняется без изменения. Проверены попадания на четырёх высотах, +1 и следующая клетка резерва. Направления оригинал берёт из свободно бегущего таймера; у нас seeded RNG. Стартовые/смертельные сценки, точная блокировка на время луча и звуки остаются адаптацией.

## Остальные игры и рейтинг

У B0202, E23 и E88 найдены аналоги стрельбы и строительства; они не автоматически доказывают правильность наших спрайтов, генераторов, коллизий и волн. У B0202/B0302 гоночная машина занимает пять рядов, у нашего донорского профиля другая геометрия. Такие расхождения фиксируются отдельно от уже измеренных исправлений; один найденный спрайт не позволяет безопасно заменить всю игру.

Для Sea Battle, Romeo, Tank, головоломок, Columns/Dr. Mario, дополнительных гоночных/стрелковых правил и музыкальных игр надёжное соответствие конкретной проверенной прошивке не установлено. Их источники и оценки сохраняются; слово «ROM» не повышает оценку только за похожее название. Отдельные сегментные Pin Ball, Puyolin и тематические LCD из Other LCD Games не считаются эталонами иной игры без установления соответствия правил.

У Snake, Dice, Frog и Honeybee **ruleset 2**. Это начинает пустые общие таблицы и новые локальные ключи; старые результаты не смешиваются с новыми. Остальные игры, в том числе Mario/Tetris, сохраняют категории и рекорды. Старые DO не удаляются физически, но не обслуживаются как текущие категории. Подробнее — [leaderboards.md](../leaderboards.md).

Оценка 90% в энциклопедии означает проверку по дампу в указанном объёме. Для Frog/Honeybee она относится к основному ROM-варианту; прочие варианты и явно перечисленные адаптации не становятся от этого подтверждёнными.
