# Ревью классических игр по BrickEmuPy

Дата: 17 октября 2026. Эталон общих правил по выбору владельца — **Apollo B0202**; для отсутствующих игр проверены также E‑23 и E‑88. Mario в эту работу не входит.

Источник: [azya52/BrickEmuPy](https://github.com/azya52/BrickEmuPy/tree/376cca92c6d000ffd6046e5491f2a1c3d1a5eab0), закреплённая ревизия `376cca92c6d000ffd6046e5491f2a1c3d1a5eab0`. Это исполнение машинного кода, а не переписанный по памяти симулятор. Однако наличие ROM не доказывает тождество другой модели или отсутствие ошибок самого эмулятора. [Статья автора об извлечении ROM E‑23](https://habr.com/ru/articles/773040/) описывает происхождение исходного материала.

## Воспроизводимость и пределы измерения

В репозитории сохранены **наблюдения**, не ROM: [fixtures](../../tests/fixtures/brickemu/b0202.json), [headless-стенд](../../scripts/research/brickemu_probe.py), карты адресов LCD B0202 и E‑23. Стенд требует только Python standard library и отдельный чистый checkout BrickEmuPy указанной версии; PyQt и звуковое устройство не нужны.

```sh
git clone https://github.com/azya52/BrickEmuPy /tmp/BrickEmuPy
git -C /tmp/BrickEmuPy checkout 376cca92c6d000ffd6046e5491f2a1c3d1a5eab0
python scripts/research/brickemu_probe.py \
  --upstream /tmp/BrickEmuPy --output /tmp/brickemu-observations.json
diff tests/fixtures/brickemu/b0202.json /tmp/brickemu-observations.json
```

Стенд считает **такты CPU**, а не время Python или производительность компьютера. В fixture записаны SHA‑256 ROM и конфигураций десяти устройств. Карты LCD извлечены из `Apollo126in1B0202.svg` и `E23PlusMarkII96in1.svg` закреплённой версии; E‑88 использует ту же адресацию матрицы, что E‑23. Исходный код эмулятора не входит в браузерный bundle.

- B0202: SPL02, частота конфигурации 690000 Гц, интервал игрового таймера 2048 такта. Эта RC-частота — параметр эмулятора, **не измерение физического экземпляра осциллографом**.
- Падение: реальные нажатия, 10 скоростей H01, чтение матрицы через 10 мс. Удержание кнопок — 600 мс, выборка через 5 мс. В сырых снимках возможна частично перерисованная LCD RAM; такие снимки не считаются отдельным движением фигуры.
- Очки/границы: обычными нажатиями получена вертикальная I; затем **искусственно подготовлены RAM поля, десятичные цифры счёта и регистр SPEED** для точного завершения 1–4 рядов и переходов 99/999. ROM и выполняемый код не меняются. Это проверка переходов из заданных состояний, а не запись естественно сыгранной длинной партии.
- Звук: команды частоты/громкости отдельных каналов и их циклы. Переходные значения при раздельной записи регистров короче 0,1 мс исключены.
- E‑23: выборка вариантов Tetris и запуск 93–96. E‑88: запуск всех восьми пунктов. Сохранены клетки после старта и удержания ROTATE; это **проверка состава и наблюдаемого действия**, не полная проверка побед, очков и коллизий.

Обычный CI использует сохранённые трассы: `tests/brick/rom-reference.test.ts`. Он не скачивает ROM. Тесты проверяют накопленный интервал падения, очки/скорость, паузу и границы ввода, а не только равенство наших констант между собой.

## Подтверждённые исправления

| Аспект | Было | Стало и основание |
| --- | --- | --- |
| Падение Tetris | линейные 480→180 мс | таблица ROM `0x0C38`: `[150,120,100,82,60,41,35,31,27,25] × 2048 / 690000` с |
| Округление | целый период в кадрах | дробный период с переносом остатка; отображение на 60 Гц без накопления ошибки |
| Рост скорости | каждые 100 очков; после максимума сброс и мусор | каждые 1000 очков, предел SPEED 9 (внутри 10); LEVEL и поле не меняются |
| Удержание ROTATE | повтор каждые 270 мс | один поворот на нажатие, как в наблюдаемой прошивке |
| Повтор LEFT/RIGHT | каждые ≈90 мс | задержка ≈130 мс, далее один кадр между сдвигами; **первый сдвиг намеренно мгновенный**, без стартовой задержки оригинала |
| DOWN | ≈33 мс и иногда дополнительный шаг гравитации | шаг раз в кадр; сброс гравитационного таймера исключает двойной шаг |
| Сдвиг/поворот Tetris: звук | приблизительные глиссандо из донорской записи | дискретные частоты/длительности/громкости команд B0202; у поворота отдельный шумовой канал |
| START/PAUSE | Enter после старта не приостанавливал игру | одинаковое действие старта/паузы/продолжения; проверка оболочки трёх Apollo |
| Simon/Dance | события `tone` терялись в BrickAudio | игровые тоны синтезируются на время из события и имеют приоритет над джинглом |

Очки за 1/2/3/4 ряда **1/3/7/15** уже были верны для B0202. Стенд подтвердил 99→100 без повышения скорости, 999→1000 с повышением, и сохранение максимальной скорости. Таблица миллисекунд: **445,217 / 356,174 / 296,812 / 243,386 / 178,087 / 121,693 / 103,884 / 92,012 / 80,139 / 74,203**.

Тоновый профиль применяется к общему семейству Tetris (включая Pentix и flicker). Это выбранная общая основа, **не измерение всех специальных вариантов**. Донорские надбавки +50 мс за Pentix и смену фигур, наборы/частоты фигур, сцены стирания и номерная сетка вариантов остаются допущениями. Быстрый FIRE по ранее принятому решению владельца не возвращён в управление Apollo.

Исправление Simon/Dance — дефект маршрутизации нашего приложения; оно **не означает подтверждения мелодий ROM**. Звуки площадок остаются собственным условным набором.

| `obstacle-race`, `boat-racing`, `racing-four`, `super-tank`, `racing-pickup`, `punch-racing` | подтверждённого соответствия нет | B0202 B/C не считаются доказательством этих дополнительных режимов |
| `maze`, `jigsaw`, `snake`, `lights-out`, `sokoban`, `peg-solitaire`, `reversi`, `2048`, `fill-connect` | подтверждённого соответствия нет | логика по описаниям; ROM-эталон пока не назначен |
| `whack-a-mole`, `simon`, `dance`, `matching-blocks`, `flappy-bird`, `basket`, `digger`, `helicopter-bomber`, `bowling`, `dr-mario`, `columns`, `columns-flicker` | подтверждённого соответствия нет | допущения сохранены; для Simon/Dance исправлена доставка звука |

У **E‑23** отдельная контрольная постановка ряда дала **10/30/70/150**, а наблюдаемая гравитация — примерно **340→45 мс**. Эти числа не заменяют B0202: разные прошивки действительно расходятся. Коробка неизвестной модели «126 in 1» с 100/300/700/1500 также остаётся справочным источником, не универсальным правилом.

Для **B0302, E‑33, GA888, Keychain55in1, GA878, MiconKC32 и RadioShackStackChallenge** зафиксированы наличие ROM, CPU, частота и хеши. Полная игровая проверка этих устройств **не выполнена**; некоторые имеют другую матрицу/адресацию. Поэтому «не найдено соответствия» в таблице выше не означает «игры точно нет ни в одном дампе». Непроверенное нельзя использовать как основание менять механику.

## Что остаётся проверить

1. Геометрию и переходы Frog B0202, затем гонки и оба семейства стрелялок: нужны записи исходного/конечного поля, входа, очков и времени, включая проигрыш.
2. Полные циклы мяч/ракетка и строительство E‑23/E‑88; особенно границы столкновений, повтор выстрела и начисление очков. Найденные аналоги пока не заменяют донорские реализации целиком.
3. Остальные ROM из инвентаризации; не выдавать их список за покрытие всех 55 записей.
4. В Tetris: появление/посадка, обработка верхнего ряда, все специальные режимы, генератор фигур, сцены очистки, потеря и запуск. Общие числовые исправления не делают ядро побитовой эмуляцией ROM.
5. Остальные эффекты и мелодии. В BrickEmuPy тон воспроизводится синусом, шум — случайными знаками; это способ вывода эмулятора, не доказательство формы сигнала реальной пищалки. Наш квадратный синтез с короткой огибающей и детерминированным шумом воспроизводит проверенные команды, но не заявлен как точная аналоговая модель.

Это частичное ROM-подтверждение и исправление установленных дефектов. Полный `RuleEvidence` по каждому аспекту всех игр из R13 [review-followup.md](review-followup.md) остаётся отдельной незавершённой работой.
