# Архитектура

Принцип: **ядро игры не знает про браузер.** Ввод, рендер, звук и оболочка подключаются к нему через
узкие интерфейсы, поэтому настоящие ресурсы, карты и подтверждённые правила можно подключить, не переписывая
игровой цикл, ввод и рендер.

```text
 клавиатура ─┐                                        ┌─► Canvas (render)
             ├─► ActionTracker ─► GameSession ─► Game ┤
 геймпад ────┘   (input)          (app)         (core)└─► события ─► аудио-порт / HUD
                                      ▲
 rAF + FixedStepper (app) ────────────┘          данные (content): экран, правила, ресурсы, уровни
```

## Слои и границы

| Каталог | Отвечает за | Не должен |
| --- | --- | --- |
| `src/core` | состояние и симуляция: `Game.step(inputFrame)`, поведения объектов, replay, ГСЧ | DOM, Canvas, Gamepad, аудио, часы, сеть, `Math.random()`, импорт из `input/render/app/audio` |
| `src/content` | типы схемы данных, проверка, сериализация уровня | всё то же, что и ядро |
| `src/input` | клавиатура, геймпад, привязки, настройки → логические действия | знать про игровые правила |
| `src/render` | Canvas-рендерер, масштабирование, камера, ресурсы | менять состояние игры |
| `src/audio` | порт аудио (`mute`/no-op) | воспроизводить звук по догадке |
| `src/app` | оболочка: rAF-цикл, сессия, устройства, интерфейс | дублировать правила |

Границы **проверяются автоматически**: `tsconfig.core.json` компилирует `core` и `content` без библиотеки DOM
и без типов Node, а ESLint запрещает браузерные глобалы, `Date`, `performance`, `setTimeout`, `fetch`,
`Math.random()` и импорты из браузерных слоёв (`npm run typecheck`, `npm run lint`).

## Ядро

- **Такт.** `Game.step(frame, options?)` — один логический такт, возвращает события. Размер такта (`tickRateHz`)
  задаётся правилами. Демо-частота (20 Гц) — не частота оригинального устройства.
- **Ввод ядра.** `InputFrame = { pressed, held, released }` — битовые маски логических действий
  (`left right up down jump fire start pause confirm back`). Ядро читает только `left…fire`, `start`, `pause`;
  `confirm` и `back` — команды меню оболочки.
- **Состояние.** `GameState` — простые данные (`JSON.stringify`). Идентификаторы объектов и порядок обработки
  стабильны (порядок объектов уровня). Случайность — только `core/rng` (mulberry32, состояние лежит в `GameState.rng`,
  seed — в `GameState.seed`). Демо-правила случайность не используют.
- **Фазы.** `ready → playing ↔ paused`; `playing → dead → ready` (если остались жизни) или `gameOver`;
  финиш последнего участка → `completed`; из `gameOver`/`completed` по `start` — новая игра. Переходы демо
  не выдаются за оригинальные.
- **Координаты.** Целые клетки карты (`y` растёт вниз). Видимая область, размер окна, `cellPx` и `devicePixelRatio`
  относятся к рендеру и на правила не влияют.
- **Графика ≠ коллизия.** Проходимость тайла задаёт `legend[символ].collision`; рисунок — `legend[символ].asset`.
  У объекта тип (`type`, поведение) и ресурс (`asset`) тоже независимы. Из имени спрайта или цвета ничего не выводится.
- **Движение.** Дискретное: шаг на клетку, повтор при удержании определяют правила (`move.repeatDelayTicks`,
  `repeatIntervalTicks`), а не повтор клавиш ОС. Прыжок — табличный (`jump.table`, `stepTicks`), запускается
  фронтом `pressed` (удержание повторных прыжков не даёт) с опоры, которая была под героем **в начале такта**;
  связь `up → прыжок` задаётся данными (`jump.triggers`). Снаряд проверяет **каждую клетку** пути, поэтому быстрый
  снаряд не пролетает сквозь стену или мишень. Двойной прыжок, coyote time, ускорение не реализованы намеренно.
- **События.** `shot`, `hit`, `projectileBlocked`, `jump`, `land`, `death`, `levelStarted`, `levelCompleted`,
  `gameOver`, `gameCompleted`, `phaseChanged`. Ядро ничего не воспроизводит: события получает оболочка
  (`audio.play(cueForEvent(event))`).
- **Особые механики.** Тип объекта — запись в реестре `core/behaviors.ts` (`update`, `heroTouch`, `projectileHit`,
  `solid`, описание параметров). Простые параметры меняются данными; новая механика — новый обработчик.
  JSON-языка правил и `eval` нет.

### Replay

`ReplayRecorder` пишет кадры ввода по тактам (подряд идущие одинаковые сжимаются), `playReplay(ctx, replay)`
проигрывает их на свежей игре. Формат: `format`, `version`, версия и id контента и правил, `seed`,
`frames: [pressed, held, released, повторов]`. При несовпадении версий — `ReplayError`.
Fixture `tests/fixtures/demo-walkthrough.replay.json` — прохождение обоих демо-участков; пересоздать после
намеренных изменений демо-правил/уровней: `UPDATE_FIXTURES=1 npx vitest run tests/core/replay.test.ts`.

## Цикл и ввод в браузере

`app/app.ts` вызывает `requestAnimationFrame`; в каждом кадре: опрос геймпада → `GameSession.frame(now)`
(накопитель `FixedStepper` → такты) → камера → рендер → обновление интерфейса.

- **Фиксированный шаг.** `FixedStepper` копит время, ограничивает кадр (`maxFrameMs`) и число догоняющих
  тактов (`maxCatchUpSteps`), остаток отбрасывает. Результат одинаков при 30/60/144 Гц (тест на кадрах из fixture).
  Это не гарантия одинакового *опроса живого геймпада* на разных FPS: геймпад опрашивается раз в кадр отрисовки.
- **Пауза без скачков.** `GameSession.suspend()` (скрытие вкладки, `blur`, отключение геймпада, открытие настроек):
  пауза, сброс клавиш, нейтральная синхронизация геймпада, сброс накопителя времени. Первый кадр после этого
  тактов не даёт. Продолжение — явная команда (`start`/`pause`/`confirm` или кнопка). Опрос ввода на паузе идёт.
- **Короткое нажатие не теряется.** `ActionTracker` фиксирует фронты «защёлками» в момент события; `consume()`
  раз на такт отдаёт `pressed/held/released`. На догоняющих тактах `pressed` не повторяется. Тап между тактами даёт
  `pressed+held+released` в одном кадре.
- **Несколько источников.** Объединяются по ИЛИ; одновременные противоположные направления дают нейтраль
  (независимо от источника и порядка событий).
- **Контексты.** В игре мир получает только игровые действия; `confirm`/`back` в мир не попадают. Вне фазы `playing`
  `confirm` работает как `start`. При открытых настройках мир ввода не получает (контекст `menu`).
- **Клавиатура.** `KeyboardEvent.code`; не перехватывается в полях ввода/кнопках и при Ctrl/Alt/Meta; `preventDefault`
  только для привязанных клавиш и только пока игровая область в фокусе.
- **Геймпад.** Состояние читается через `navigator.getGamepads()` на каждом опросе (объекты событий не хранятся).
  Активное устройство одно, индекс не обязан быть 0; активируется первым нажатием или выбором в настройках.
  Гистерезис стика; при активации, `sync()` и повторном подключении удерживаемое «разоружается» до отпускания.
  Для нестандартного `mapping` автоматической раскладки нет — предлагается настройка.

## Данные и рендер

Формат — [content-format.md](content-format.md). Загрузка: статические JSON → `assemblePack` (проверка всего пакета
и ссылок между файлами; ошибка — исключение `ContentError`, а не частично собранная сцена).

Рендер рисует в **логических пикселях** профиля экрана; `computeLayout` берёт наибольший целый масштаб с учётом
`devicePixelRatio` и не растягивает поле. Заглушки — битовые карты 8 × 8 (`render/glyphs.ts`); `AssetStore` умеет
рисовать и картинки-полосы кадров (PNG/SVG) с запасной заглушкой при ошибке загрузки.

## Тесты

| Что | Где |
| --- | --- |
| столкновения со всех сторон, прыжок/посадка, выстрел и попадание, смерть/рестарт, фазы, финиш | `tests/core` |
| replay: повтор даёт то же состояние, версии, сериализация, ГСЧ | `tests/core/replay.test.ts` |
| проверка данных: ошибки с путём, ссылки, версии | `tests/content` |
| фронты/удержание/конфликты, клавиатура, геймпад (мёртвая зона, отключение, реконнект), настройки | `tests/input` |
| фиксированный шаг на разных расписаниях, сессия, хаб устройств, загрузка данных | `tests/app` |
| раскладка, камера, ресурсы, аудио | `tests/render` |
| браузерный smoke | `tests/smoke` |

Ядро тестируется без браузера. Геймпад — через подставной провайдер; реальные контроллеры проверяет владелец
по [чек-листу](manual-gamepad-check.md).

## Подготовка к редактору уровней (issue #4)

Полноценный редактор появится позже. Чтобы он не потребовал второго формата или второй физики, уже сейчас:

- **Один формат уровня.** Загрузчик игры и будущий редактор используют `validateLevel`/`assemblePack`.
  `levelToJson(level)` (`src/content/serialize.ts`) возвращает канонический JSON, который проходит валидатор без
  правок; круговой тест гарантирует отсутствие потерь.
- **Адресные ошибки.** `ContentError.details` — список `{ path, message }`, например `$.rows[3][5]` или
  `$.objects[0].type`: редактор может перейти к клетке/объекту.
- **Каталог типов из кода.** `describeObjectTypes(registry)` отдаёт для каждого типа подпись, твёрдость и параметры
  (`ParamSpec`: ключ, подпись, диапазон, значение по умолчанию). Из этих же описаний строится проверка параметров.
  Новый тип добавляется обработчиком в реестр и сразу виден палитре и инспектору.
- **Запуск «из памяти».** `createContext(pack)` принимает пакет, собранный в памяти; `Game` и `GameSession` не
  зависят от DOM, `Renderer` принимает любой `<canvas>`. Тестовый запуск из редактора — те же классы с другим пакетом
  и без записи в редактируемый документ (состояние игры отделено от уровня).
- **Данные отделены от кода.** Размер карты, профиль экрана и правила — в файлах, а не в константах.

Чего пока нет и что нужно будет добавить вместе с редактором, **единым изменением схемы и загрузчика**:
общий каталог тайлов (сейчас `legend` задаётся в каждом уровне), слой исследовательских пометок
(`unknown / assumed / confirmed`, заметка, ссылка на референс — в метаданных уровня, не в симуляции),
hash-маршрут «Редактор», хранение черновиков и архив проекта.
