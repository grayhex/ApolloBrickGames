# Игры «168 в 1 танк»: ядро «кирпичных» игр

Игрушка 4 («168 в 1 танк») играет не одним тетрисом, а набором игр из меню. Исходные данные — наблюдения владельца (пункты меню, число вариантов у танков и тетриса) и карта источников
[apollo-tank168-research](https://github.com/grayhex/CrocodileMario) (донор правил — открытый симулятор [n0Live/BrickGame](https://github.com/n0Live/BrickGame), MIT).
Точного дампа ROM именно этой модели нет, поэтому **правила игр — правила донора (или допущения, помеченные в каждой игре), а не подтверждённые правила Apollo**.

У «Морского боя» (A–F): A — морской бой и C — «Ромео и Джульетта» ещё не восстановлены (в меню выбираются, не запускаются), B — танки (первые 2 варианта), D — Pentix, E — тетрис (первые 20 вариантов), F — арканоид.

## Слои

- `src/brick` — чистое ядро (без DOM, часов и `Math.random`; границу проверяют `tsconfig.core.json` и ESLint): `types.ts` (интерфейс `BrickGame`, ввод, события), `base.ts` (`BrickBase`: фазы, счёт, жизни,
  сценки, взрыв, очистка поля, конец игры), `grid.ts` (спрайты и ряды), `rng.ts`, `timing.ts` (миллисекунды → такты, `Countdown`, `Repeater`), `games/*` (игры), `console.ts` (меню: номер игры, вариант, иллюстрация).
- `src/render/tetrisScreen.ts` рисует любую такую игру: матрица 10 × 20 (0 — погашена, 1 — горит, 2 — мигает), превью 4 × 4, счёт, скорость, уровень, чашка паузы.
- `src/app/tetrisApp.ts` — оболочка: питание, звук, кнопки корпуса, меню консоли.
- `src/brick/guides/*` + `src/app/guidePanel.ts` — описания игр для левой панели (ниже).

## Как устроена игра

```ts
class MyGame extends BrickBase {
  readonly id = 'tank';
  constructor(options: BrickGameOptions) { super(options, MODES.length); /* поля */ this.init(); }
  protected reset(): void { /* новая партия: поле, объекты, setLives(4), таймеры */ }
  protected update(input: BrickInput): void { /* один такт; события — this.emit(...) */ }
  protected draw(): Uint8Array { /* матрица 200 клеток */ }
  protected drawPreview(): Uint8Array | null { /* превью 4×4 или null (по умолчанию — индикатор жизней) */ }
}
export const myDef: BrickGameDef = { id: 'tank', declaredModes: 5, modes: MODES, create: (options) => new MyGame(options) };
```

- Время — такты, 60 в секунду. Миллисекунды донора переводятся `msToTicks`; «настоящая» скорость по формуле донора — `genuineTicks(speed, msFirst, msTenth)`.
- Кнопки: `left`, `right`, `up`, `down`, `rotate` (большая кнопка, в стрелялках — огонь), `fire` (клавиша «огонь» на клавиатуре; в тетрисе — бросок, в остальных играх — как `rotate`). Автоповтор зажатой кнопки — `Repeater`.
- Скорость и уровень — 1..10 (на экране консоли показывается число минус один). `nextLevel()` повторяет донорскую победу в уровне; жизни — `setLives`, добавочная жизнь — `scoresToExtraLife`.
- Взрыв и очистка поля — `animateKaboom`, `animateClear` (как у донора); любая пауза «без ввода» — `cutscene`.
- Случайность — только `this.rng` (seeded). Одинаковое зерно и одинаковые вводы — одинаковые состояния.
- В каждой игре — список вариантов `modes` (название на двух языках и пометка, что в варианте донорское, а что — допущение).

## Описания игр для левой панели

У каждой игры из реестра `BRICK_GAMES` есть описание **«по факту реализации»** — `GameGuideData` (`src/brick/guide.ts`): краткое содержание и цель, правила (3–8 пунктов), кнопки, очки, 2–4 факта-числа, рост скорости и уровня, жизни, 1–3 схемы клетками (`#` горит, `*` мигает,
`.` пусто — не больше 10 × 20), допущения (≤ 5). Все тексты — на двух языках (`gt(ru, en)`), длины ограничены `GUIDE_LIMITS`, форму проверяет `guideProblems`. Описание лежит в `src/brick/guides/<игра>.ts` и **строится по коду игры**: числа берутся из экспортируемых констант игры
(жизни, очки, пороги, скорости), поэтому текст не может разойтись с кодом без сбоя теста; реестр — `src/brick/guides/index.ts` (`BRICK_GUIDES` по идентификатору каталога; «Тетрис с большими фигурами» и «Тетрис Pentix» — одно описание).
Панель рисует его в `src/app/guidePanel.ts`; варианты берутся из `BrickGameDef.modes`.

**Что пишется в описание.** Только игра: цель, правила геймплея, кнопки, очки, рост скорости, жизни. Логика воссоздания — звук и заставки, происхождение чисел («по ROM», «по записи владельца»), оговорки о неподтверждённом, ограничения реализации — в правила, `progression` и `lives` не попадает: она живёт в `assumptions`, которые энциклопедия показывает отдельным блоком под источниками (`src/encyclopedia/page.ts`). Исправлено 2026-10-27: куплет «Коробейников» и сцена с флагом у Mini Brick, «адаптация», «ещё не подтверждено дампом», «по описанию вики» и т. п. перенесены в допущения.

Новая игра = модуль в `games/` + `BrickGameDef` + запись в `BRICK_GAMES` + `guides/<игра>.ts` + запись в `BRICK_GUIDES` + тесты (`conformance`, правила, `<игра>.guide.test.ts`) + документ в `docs/brick/`.
Что считать допущением: всё, чего нет в коде донора (`n0Live/BrickGame`) и чего мы не видели на устройстве; в описании — только настоящие допущения, остальное («не установлено») — в документе игры.

## Источники и доказательность

- **n0Live/BrickGame** (MIT) — единственный источник, из которого перенесены правила (с уведомлением в [THIRD_PARTY.md](THIRD_PARTY.md)); значения «донорского» кода не считаются подтверждёнными на Apollo.
- **vitalibo/Brick-Game-9999-in-1** — **лицензии нет**, код не переносился и не цитируется: источник для сравнения идей (карта — [research/apollo-tank168-brick-game-sources.md](research/apollo-tank168-brick-game-sources.md)).
  Из него следует, что «9999» — номер меню по кругу пяти игр, а не тысячи вариантов; пяти режимов танков, стен, базы и таблицы уровней в нём нет, и мы их **не придумываем**.
- **brick.game** — только справочный стенд для визуального сравнения; не спецификация и не донор кода.
- **Описания MT1997** (другая модель Brick Game) — основание для «фигур» и «гонок со стрельбой»; правил Apollo не дают.
- Дамп прошивки Apollo не найден. Что происходит на устройстве на самом деле — «не установлено», пока владелец не сверит по видео или фото; соответствие номеров вариантов устройства вариантам донора везде — допущение.

## Как проверять

`npm run typecheck`, `npm run lint`, `npx vitest run` (игры — `tests/brick/games/*`; описания — `tests/brick/guides.test.ts` и `*.guide.test.ts`), `npx playwright test` (нужна переменная `CHROMIUM_PATH`): меню консолей — `switch.spec`, `toys.spec`;
вкладки и описания — `guide.spec`; **сами игры в браузере** (выбор в меню, запуск, управление, чашка паузы, RESET, режимы «Морского боя») — `games.spec`.
