# Статус референсов: что известно об оригинале

Проект — **реконструкция** Apollo Crocodile Mario по наблюдениям владельца устройства, а не эмулятор.
Этот файл разделяет три вещи, чтобы догадки не превращались в «факты»:

1. [Подтверждено владельцем](#1-подтверждено-владельцем)
2. [Demo-допущение движка](#2-demo-допущения-движка-временные-значения)
3. [Предстоит измерить на устройстве](#3-предстоит-измерить-на-устройстве)

Отдельно — [наблюдения по фотографиям](#наблюдения-по-фотографиям-не-измерения): они помогают
выбрать разумные временные значения, но **не являются измерениями** и в правила не попадают.

В коде и данных всё неподтверждённое помечено `status: "demo"` (см. [content-format.md](content-format.md)).
Когда параметр измерен, его меняют на `confirmed` вместе со ссылкой на источник в этом файле.

## 2. Demo-допущения движка (временные значения)

Все значения лежат в данных (`public/content/demo/`) или помечены в коде как demo. Менять их можно без правки движка.

| Область | Допущение | Где |
| --- | --- | --- |
| Темп симуляции | 20 логических тактов в секунду | `rules.json → tickRateHz` |
| Движение | дискретный шаг на 1 клетку; повтор при удержании: пауза 4 такта, затем каждые 3 | `rules.json → move` |
| Прыжок | табличный: `[-1,-1,-1,0,0]`, одна фаза = 2 такта; запускается нажатием (фронтом), не удержанием; с опоры, которая была под героем в начале такта | `rules.json → jump` |
| Падение | 1 клетка за 2 такта | `rules.json → fall` |
| Выстрел | интервал 4 такта, повтор при удержании, не более 2 снарядов, 2 клетки за такт, дальность 10 | `rules.json → fire` |
| Жизни, таймер, смерть | 3 жизни; таймер участка 90 с; пауза смерти 1 с | `rules.json` |
| Переходы фаз | `ready → playing ↔ paused`, `playing → dead → ready` (если есть жизни) или `gameOver`; финиш последнего участка → `completed`; из `gameOver`/`completed` по `start` — новая игра | `src/core/sim.ts` |
| Очки | мишень 100, патруль 200, финиш 500/1000 | параметры объектов уровней |

| Камера | следует за героем с «мёртвой рамкой» 30 %; не часть ядра | `src/render/camera.ts` |
| Уровни `demo-1`, `demo-2` | искусственные тестовые участки | `levels/` |
| Подпись HUD | `D-1`, `D-2` — просто метка демо-участка, не формат оригинала | `hudLabel` |

## 3. Предстоит измерить на устройстве

Ничего из этого не реализовано «по догадке»:

- разрешение LCD, число столбцов и строк игрового поля, размер и пропорции клетки, отступы HUD;
- число уровней/миров, структура уровней, смысл индикатора вида `1-03` (в коде это просто подпись);
- точная физика: высота и фазы прыжка, период падения, шаг и повтор движения, тайминги;
- стрельба: есть ли она во всех режимах, интервал, скорость, лимит пуль, дальность;
- враги и опасности: типы, движение, поведение при столкновении;
- очки, жизни, таймер (есть ли таймер вообще), условия победы и поражения, переход между уровнями;
- что делает кнопка S./P. (старт и пауза — одна кнопка), как ведёт себя SOUND и ON/OFF;
- логика трёх светодиодов над экраном; звуки;
- как прокручивается широкий уровень (и прокручивается ли);
- остальные режимы устройства (на одном корпусе видна надпись о наборе игр — тетрис, «танк»; в этот проект не входят).

## Наблюдения по фотографиям (не измерения)

Владелец показал в чате шесть снимков (четыре кадра включённого экрана, красный корпус с выключенным экраном и три закрытых корпуса).
**Файлов в репозитории нет** — другой исполнитель их не увидит; владельцу нужно добавить исходники
(см. [references/README.md](references/README.md)). Ниже — только то, что на снимках различимо.
Качество снимков низкое (кадры видео, перспектива, блики), поэтому всё ниже — ориентир, а не данные.

- **Корпус.** Раскладушка: в верхней половине экран, над ним три светодиода (красный, жёлтый, зелёный),
  под экраном нанесён рисунок (три персонажа и гора). В нижней половине кнопки.
- **Кнопки** (красный корпус): верхний ряд подписан `ON/OFF`, `S./P.`, `SOUND`, `FIRE`; крестовина с подписями
  `UP`, `LEFT`, `RIGHT`, `DOWN`; отдельная крупная кнопка `JUMP`.
  Отсюда — выбор раздельных действий `up` и `jump` и одной связки start/pause для кнопки Start геймпада.
  Это наблюдение о кнопках, а не о том, как игра на них реагирует.
- **Экран.** Монохромный: светло-серая подложка, тёмные серо-синие сегменты. Верхняя строка: слева мелкие
  значки (на снимках 2–3 штуки, назначение не установлено), по центру группа вида «цифра-дефис-две цифры»,
  справа пятизначное число. Встречавшиеся значения: `1-03 / 00000`, `3-01 / 00300`, `1-02 / 00110`, `1-09 / 00010`.
- **Поле.** Блоки с внутренним рисунком (не сплошные квадраты); на одном кадре поле почти целиком заполнено
  блоками с несколькими пустыми ячейками, на других — пол и ступени. Герой — маленькая фигурка размером примерно в одну
  ячейку. На одном кадре справа от героя виден тёмный объект поменьше (возможно, снаряд; не подтверждено).
- **Размер сетки по фото.** По ширине блока оценка — примерно 13–15 столбцов, строк поля 6–8 плюс строка HUD;
  ячейки на некоторых кадрах выглядят чуть шире, чем высота (ракурс может это искажать).
  Для демо взято 13 × 7 — это **оценка**, проверять нужно по резкому снимку включённого экрана.
- **Палитра.** Серый фон и тёмно-серые сегменты, а не зелёный «Game Boy». Для демо #1 оставлена нейтральная
  зеленоватая палитра движка; палитра «по фото» — задача #2.
