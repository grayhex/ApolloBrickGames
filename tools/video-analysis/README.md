# Анализ видео фрагмента (наблюдения, не правила оригинала)

Скрипты, которыми получены числа в [docs/video-observations.md](../../docs/video-observations.md). Видео в репозиторий не
входит (файлы владельца: `Video_Project_3.mp4`, 1280 × 720, без звука — экран и физика; `Video_Project_6.mp4`, 852 × 480, 37,6 с, **со звуком** — звук и светодиоды; видео геймплея `Apollo-Tetris-Crocodile … .mp4`, 640 × 360, 326,5 с — уровни).
Нужны Python 3, `opencv-python`, `numpy` и `ffmpeg`; для звука ещё `scipy` и `matplotlib`. Скрипты по первому видео запускаются из каталога с `in.mp4`, по порядку:

| Скрипт | Что делает | Результат |
| --- | --- | --- |
| `stabilize.py` | ORB + RANSAC-гомография каждого кадра к эталонному (кадр 15), выпрямление LCD-поля в 520 × 284 | `lcd_full.npy`, `lcd_small.npy`, `stab.json` |
| `cells.py` | сетка 13 × 6 (шаг 37,9 × 37,0 px, начало 15, 58), «чернильность» клетки | функция `ink_matrix` |
| `timeline.py` | матрица занятости клеток по кадрам и список изменений (`#` — блок, `+` — частично, `.` — пусто) | `ink.npy`, текст в stdout |
| `hero.py` | шаблон героя (кадры 136–139, клетка (5,1)) и поиск по клеткам (NCC) | `hero_resp.npy`, `hero_tpl.png` |
| `audio_leds.py` | проверка звуковой дорожки (RMS) и яркости трёх светодиодов по кадрам | текст в stdout |

Звук и светодиоды (второе видео, [раздел 8](../../docs/video-observations.md#8-звук-и-светодиоды-запись-со-звуком)); аргументы — в начале каждого скрипта:

| Скрипт | Что делает | Результат |
| --- | --- | --- |
| `audio_spectrogram.py in.mp4 out/` | извлекает дорожку (моно 44,1 кГц) и строит спектрограмму до 6 кГц с громкостью | `out/audio44.wav`, `out/spectrogram.png` |
| `audio_notes.py out/audio44.wav от до` | основной тон по кадрам STFT (сумма нечётных гармоник) и сегменты «нота — длительность»; ноты — полутоны от 762 Гц | текст в stdout |
| `led_chase.py in.mp4 [от до]` | цветные пятна трёх светодиодов, «белизна» окна, порог Оцу, сжатая шкала «горит — не горит» | текст в stdout |

Как из этого получена мелодия: ноты по `audio_notes.py` на двух заходах мелодии совмещены по сетке 135,6 мс (аккорды двух заходов), стрельба поверх мелодии вычиталась
сравнением заходов; светодиоды сопоставлены с нотами при сдвиге по времени (светодиод опережает дорожку ≈ 0,19 с — сдвиг записи). Итог — `src/audio/phrases.ts`.

Видео геймплея (третье, 640 × 360, 326,5 с, [раздел 9](../../docs/video-observations.md#9-видео-геймплея-устройство-уровней-девять-геймплейных-уровней)); результат — карта уровня по клеткам:

| Скрипт | Что делает | Результат |
| --- | --- | --- |
| `gameplay_lcd.py in.mp4 out/ [шаг=3]` | ORB + RANSAC совмещает каждый третий кадр с опорным (60 с) и выпрямляет LCD в 432 × 216 (1/4 логического 1728 × 864) | `out/lcd.npy`, `out/meta.json` |
| `gameplay_world.py ink out/` | занятость клеток 13 × 6 по каждому кадру (тёмная доля после вычитания фона) | `out/ink.npy` |
| `gameplay_world.py stitch out/ от до` | склейка кадров по прокрутке (сдвиг −2…+2 столбца), новая попытка — по экрану «ямы»; печать карты `#`/`+`/`.`/`?` | текст в stdout |
| `gameplay_world.py consensus out/ от до [от2 до2]` | карты попыток совмещаются (±6 столбцов) и голосуют | `out/cons.npy`, `out/cover.npy` |

Из полученной карты руками (± 2 столбца) снята цепочка платформ уровня 1 — она вошла в `tools/levels/generate.mjs` (`measuredStart`); остальные уровни генератор строит по правилам. Четыре угла LCD в опорном кадре заданы вручную в `gameplay_lcd.py` (`QUAD`).

## Генератор уровней

`tools/levels/generate.mjs` (Node, без зависимостей) пишет девять геймплейных уровней `public/content/room/levels/mario-1…9.json`, список уровней в `pack.json` и сценарии интро/входа в `animations.json`;
результат детерминирован (зерно на уровень), готовые файлы лежат в репозитории. `tools/levels/reach.json` — таблица пределов прыжка (сверяется с движком тестом), `tools/levels/overview.mjs` рисует
`docs/screenshots/levels-overview.png`. Проходимость проверяет `tests/core/mario-levels.test.ts` (решатель `tests/helpers/solver.ts`).

Четыре угла LCD в эталонном кадре заданы вручную в `stabilize.py` (`quad`) — для другого видео их нужно переставить.
Точность по времени — ±1 кадр (±33 мс).
